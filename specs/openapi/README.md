# OpenAPI Specs

Coloque aqui contratos REST aprovados.

## Objetivo
- Tornar endpoints implementaveis sem ambiguidade
- Permitir testes de contrato em `tests/contract/`
- Evitar que agentes inventem payloads

## Convencoes
- Um arquivo por bounded context ou API
- Versione breaking changes explicitamente
- Referencie os ADRs relevantes no cabecalho do arquivo
